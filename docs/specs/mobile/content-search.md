# App 内内容查找与整理

> 状态：Approved（需求已确认）；执行前仍需核实环境和技术准备条件。
>
> 最后更新：2026-10-12
>
> 关联需求：[PROD-004、PROD-005](../../product/maat-product-spec.md)
>
> 本文定义首轮用户任务验收，不代表已经执行、实现完成或验收通过。

## 1. 用户目标

Pi 用户向 Agent 指定主题，Agent 借助 Maat 在指定手机的 App 内查找和阅读内容，
将实际读到的内容整理成有可核对来源的结果。

## 2. 已确认范围

| 平台           | App  | 任务                                             |
| -------------- | ---- | ------------------------------------------------ |
| Android 物理机 | X    | 搜索指定主题，阅读相关帖子，整理结果             |
| iOS 物理机     | 微信 | 通过“搜一搜”搜索指定主题，阅读相关文章，整理结果 |

平台和 App 的实现可以不同，但用户目标和基础成功标准相同。
测试只能说明这两条具体路径的覆盖情况，不能推广为任意 App 都可用。

### 已确认的任务指令

> 帮我在手机上的 X／微信搜一搜，查找 3 条关于 AI 编程助手的使用经验。
> 实际打开阅读后，逐条整理主要观点，并提供作者、帖子或文章标题等可核对的来源。
> 只查找和阅读，不发布或发送任何内容。

每个平台分别完成 3 条，不将两端结果合并计算。
两端无需找到相同内容。

## 3. 基础验收标准

### AC-SEARCH-001：真实用户入口

由真实 Pi Agent 通过 Maat Extension 操作用户指定手机上的 App。
脚本驱动的设备检查和 Mock 测试不能替代此用户路径。

### AC-SEARCH-002：按用户目标搜索

主题为“AI 编程助手的使用经验”，结果应包含实际使用经历或体验，
仅提及 AI 编程助手名称的内容不能自动视为满足要求。
Agent 可以选择检索词和操作步骤，但不能更换主题来制造通过。

### AC-SEARCH-003：实际阅读与结果来源

每端实际打开阅读 3 条不同的相关内容，不能只读取搜索结果标题。
逐条整理主要观点，提供 App 中实际可见的作者、
文章标题或帖子识别信息等可核对的来源，不编造未显示的来源字段。
不得凭模型记忆补写未读到的内容，不得改用浏览器网页完成本轮手机任务。
摘要与原文是否一致、来源是否可核对必须在验收中检查，不能只检查数量。

### AC-SEARCH-004：如实暴露阻塞和未满足结果

未找到相关内容、无法访问、需要登录或设备不可用时，明确说明实际情况。
不能把连接成功、搜索动作成功或空结果冒充用户任务完成。
登录等人工步骤遵循现有安全边界，不自动代办。
不足 3 条时如实给出已读结果和未满足条件，不降低数量要求或补造内容来算通过。

### AC-SEARCH-005：查找和阅读边界

不发送消息、发布内容、点赞或关注，不把本轮确认扩大为这些操作的授权。
其他设备与数据操作遵循 [AGENTS.md](../../../AGENTS.md) 的现有安全约束。

### AC-SEARCH-006：双平台独立验收

Android 和 iOS 分别记录实际用户路径和逐条验收结果。
一端通过不能替代另一端通过；两端必要标准都满足才算本轮双平台任务完成。

## 4. 已确认的验收起点与观测指标

复用现有电脑、Pi 和 Maat Extension，目标 App 已安装且已登录。
不要求全新安装，不重装 App 或清理设备数据。

从用户向 Pi 发出任务开始，由 Pi 检查准备情况、建立或复用连接，再完成任务。
不由验收者预先代跑连接或操作来隐藏用户路径中的准备问题。
已有健康 Session 或服务可以正常复用，不强制制造冷启动。
解锁、认证等本人步骤允许人工处理，记录步骤和实际影响，不隐藏人工介入。

每端记录任务耗时、尝试次数和人工介入，
首轮不设置时间或尝试次数的通过门槛。
这些观测指标用于后续体验需求，不把本轮任务通过描述为全新机器安装即用通过。
已有设备连接、计算器或恢复记录不回填为本轮任务通过。

本轮讨论仅确认需求和验收起点；真实设备执行前须核实目标设备及操作授权。

## 5. 非目标与相关设计

本用例不是固定的 X 或微信操作脚本，也不要求在 Maat 中新增 App 专用业务逻辑。
Agent 根据当前界面选择操作；设备基础设施参考
[设备管理技术设计](../../maat-mvp-technical-design.md)。

发送消息的授权流程、全平台 App 兼容声明以及设备管理重建全部 Gate 的完成，
均不属于本用例单独通过所能证明的范围。
